## 冒頭で伝えること

- 「あなたの駅は、何Tier？」という遊びとして紹介。
- 公開した「にぎわいの地形図」の山の高さを、駅ごとのカードで並べた。
- SS / S / A / B / C / Dの通常のTier表。利用者が好みでカードを動かす方式ではなく、データから自動配置。
- お店・施設の**登録の集まり**を比べるもの。実際の人出・人気・売上・駅の優劣を測定したランキングではない。

## 読者ができること

- 全国 → 都道府県 → 市区町村で絞る。「東京都・練馬区」なども選べる。
- 路線名・会社名の一部、駅名で検索。地域と組み合わせられる。
- 絞っても全国基準のTierは変わらない。各Tier内は密度の大きい順。
- 条件に合う全件を表示。「さらに表示」を何度も押す方式ではない。
- カードは駅名・電車アイコン・地域・整数の密度。同名駅が残る場合は路線・事業者の補足。
- カードを押すと密度・判定理由を表示。そこから地形図の対応する峰を直接開ける。
- Tier見出しには「上位約1%」などを控えめに表示。押すと密度基準・全国該当数・母集団を説明。
- 峰のない駅の数値は「—」。0密度の意味ではない。

## 全国の収録範囲

- 47都道府県、**9,032駅カード**。
- 国土数値情報N02の9,046駅グループを基本に、同名・同一市区町村で全メンバー間500m以内の14組を統合。
- **5,406駅に対応する峰があり、3,626駅は「峰なし」**の別枠。
- 最新の全実在駅を独自に現地確認した意味ではない。収録した駅データの範囲に対する全国版。
- 異名の乗換駅はまだ統合していない。同じ名前でも遠隔地や別の駅として残る場合がある。

## 数値の意味・地形図との関係

- 指標は**対応する峰の最大登録密度（件/km²）**。駅の参照IDで照合し、複数の峰があれば最大値を使う。
- 地図と同じ密度を使い、統合した駅でも密度を足し合わせない。
- 駅そのものの所在地の密度、駅周辺の実店舗数、都市全体の総店舗数ではない。
- 計算条件は全業種・ガウス平滑化の標準偏差200m。半径200m内だけを数える方式ではない。
- 池袋 **15,952**、渋谷 **20,383**、銀座 **22,414件/km²**。
- 「峰なし」は参照駅IDに対応する局所最大点がないこと。お店がないという意味ではない。新宿駅そのものも、峰が近隣駅の名前に割り当てられているため峰なしになり得る。
- 地形図は800件/km²未満を表示しないが、Tier表はそれ未満の計算済み峰も含む。地図上で▲が見えない駅がある理由として必要なら補足。
- 原宿周辺の11,936件/km²の峰は明治神宮前に対応。表示は公式表記「明治神宮前〈原宿〉」に補足し、原宿でも検索できる。JR原宿とは別カード。

## Tierの基準

**母集団は、対応する峰がある全国5,406駅。峰なし3,626駅は含めない。**

| Tier | 全国での区分の目安 | 密度基準の表示目安（件/km²） | 駅数 |
| --- | --- | --- | ---: |
| SS | 上位約1% | 約6,524以上 | 55 |
| S | 上位約1〜5% | 約2,188以上、SS未満 | 216 |
| A | 上位約5〜20% | 690以上、S未満 | 813 |
| B | 上位約20〜50% | 236以上、A未満 | 1,623 |
| C | 上位約50〜80% | 94以上、B未満 | 1,627 |
| D | 残りの約20% | C未満 | 1,072 |

- 同じ密度を境界で分けないので、割合はぴったり一致しない。
- 数値・基準は整数で表示。判定と並び順は丸める前の値を使う。
- 区分はこのサービスで設定したもの。一般的な格付け基準や統計的に最適な境界ではない。

## 作り方を短く説明するなら

- Foursquare OS Placesの2026年9月15日版から密度の地形図を作った。
- 密度の局所最大点を峰とし、近くの駅などを参考名にした。
- その峰の参照駅IDをN02の駅台帳へ照合し、駅ごとの最大密度を取り出した。
- 全国の密度分布からTier境界を計算し、ブラウザで検索・絞り込みできるようにした。
- GitHub Pagesで静的配信。地形図は既存のS3＋CloudFrontを使用。
- **旧試作の「800m内のPOIを駅へ割り当て、距離で重み付けした点数」は現在使っていない。** 9,096点の池袋という古い画面・説明は記事に使わない。

## 限界として本文に残すこと

- 国・地域によって登録の充実度が違う。営業状況・位置・重複・地名を全件確認していない。
- 閉店判明分と一部の位置品質保留を除いているが、営業中・正位置の保証にはならない。
- 峰をどの駅に名付けるか、同名駅をまとめるかで結果が変わる。
- 日本語名はできる範囲で整えた表記。読みや位置をすべて保証するものではない。
- 見て楽しむ、別の資料を調べる入口として使う。訪問・施設利用は公式情報などでも確認してもらう。
- 経済センサス比較、突出度による独立峰判定を実施済みと書かない。

## 初期表示・ロードに触れる場合

- 最初は東京に絞って開き、全国は利用者が選べる。
- 全駅情報を維持したまま、配信用JSONを約3.54MBから約1.16MBへ軽量化（展開後サイズ）。先読みと読み込み中の表示も追加。
- 通信量は圧縮のため別の値。本番計測では旧約435KB、新約348KBだった。端末・回線によって待ち時間は変わり、実機全般の速度保証ではない。
- 「約3倍速くなった」とは書かない。全国を選ぶとカード数が多い点は残る。

## CSVを併記する場合

- 世界の[全峰CSV・23,187地点](https://github.com/isshiki/nigiwai-topo/raw/refs/heads/main/exports/world-2026-09-15/world-peaks.csv)と[地名代表CSV・14,563地点](https://github.com/isshiki/nigiwai-topo/raw/refs/heads/main/exports/world-2026-09-15/world-place-representatives.csv)は地形図のデータ。
- **全駅のTierデータCSVではない。** 対象範囲・粒度・下限が違うので、駅Tier表をそのまま再現できるCSVとして案内しない。
- 詳細：[世界CSV説明](../exports/world-2026-09-15/README.md)。ダウンロード案内は記事へ置き、地図画面からは外している。
