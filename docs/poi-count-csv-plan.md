# 商圏の参考用POI件数CSV：検討案（未実装）

## 推奨する初回仕様

- 全業種・同じ2026-09-15固定データを対象に、まず日本で固定の1kmメッシュへ登録件数を集計する。世界へ広げる場合も緯度経度1度を1kmとみなさず、面積と距離の扱いを定義する。
- 配布単位は国／地域。画面と同じS3＋CloudFrontで配布し、圧縮CSVと列・集計方法の説明を用意する。
- 列候補：区域ID、代表緯度経度、区域面積km²、登録件数、件数÷面積、データ日付、集計条件。区域をGISで再利用できる境界データも併せて提供する。
- 0件と未計算・対象外は区別する。800件/km²の画面下限でCSVを切り捨てない。
- 個別POI名・住所を配布せず、地域集計から始める。出典とNOTICE、名称・区域の出典条件を添付する。

## 画面の数値と区別

- 山頂の密度はσ200mでならした件/km²。区域の登録件数ではない。
- 現在のトップ20をCSVにする場合は「峰の密度ランキング」と明記し、商圏のPOI数として配らない。
- 商圏境界を既に定義できているわけではない。将来の任意半径／ポリゴン集計は別機能として検討する。半径集計は重複範囲があり、単純な合計に使えない。
- 原本全体の重複解消・施設の営業確認はしていないため、列名は実店舗数ではなく登録件数とする。
- 閉店判明分と位置品質の計算保留を除く。世界の生成入力と照合し、表示範囲外・極域などを別集計して全入力と帳尻を合わせる。

## 公開前の検証

- 境界上の点の割当規則を固定し、同じ点を二重計上しない。
- 原本の採用件数とメッシュ集計の合計を比較。サンプル地域は別実装で照合。
- メッシュは商圏の境界ではないこと、登録偏り・位置ずれ・古い情報・重複の限界をREADMEに書く。
- 人口・交通・売上などとの併用を促し、出店の成功や需要を直接予測する指標とはしない。

現在は設計案のみで、CSVの生成・配布・ダウンロードボタンは未実装。
