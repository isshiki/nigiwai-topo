# 計算方法と限界（現在の世界版）

現在の公開条件は全業種・σ200m・表示下限800件/km²。日本も世界共通の計算結果を表示する。旧日本の100m正積投影版とは格子・方法が異なる。

## 密度

- `scripts/global_density.py`：経度400,000、緯度200,000区間の共通格子（ともに0.0009度）。赤道付近で約100m、高緯度では東西幅が狭くなる。
- POIを格子へ集計し、ガウスカーネルで平滑化。σ200mは標準偏差で、半径200m以内だけを集計する方式ではない。
- WGS84測地線による行ごとの実距離・面積を使い、東西カーネル・南北重み・件/km²への換算を補正。経緯線方向に分離した近似で、厳密な球面KDEではない。
- 区画の外側に4σ以上の計算余白を用意。日付変更線の周期入力と共有辺を扱う。極域の完全網羅を主張しない。
- 閉店判明分と位置品質の計算保留を除く。閉店情報がない登録を営業中と確認した意味ではない。

## 地形と峰

- `scripts/build.py`のcontourpyで密度から段彩の面・等高線を作る。密度の計算値：100/200/400/800/1000/1600/2000/3000/4000/6000/8000/12000/16000/20000/24000/32000。公開では800未満を描かない。
- 計曲線は1000/2000/4000/8000/16000/32000。遠景は段彩を簡略表示、拡大で等高線を表示。
- 3Dの描画高さは「帯の下限密度−800」の非負部分の平方根×6。実標高のメートルではない。
- 峰候補は9×9近傍の局所最大点、計算上の最低密度50。区画外により高い密度がある端の候補は境界再評価で補正。
- 突出度による独立峰判定は未実装。同じ参照地名の峰は画面内の最高密度を代表にして、ランキング上位20件を出す。都市の総登録数や独立商圏の順位ではない。

## 配信・限界

- 密度形状をPMTiles、峰を分割JSONと索引にし、表示範囲に必要なデータを取得。画面はGitHub Pages、地図はS3＋CloudFront、描画はMapLibre GL JS。
- 国・地域による登録偏り、重複・古い登録・誤位置、近似計算、格子やσによる見え方の違いがある。無色は登録ゼロの証明ではない。
- 名称の日本語化は位置や発音の全件保証ではない。[地名の方針](world-display-names.md)。
- 経済センサス比較、平滑化幅を変えた世界順位の感度検証は未実施。
