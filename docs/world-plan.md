# 世界版に向けた残作業

GitHub Pagesへの画面公開は世界版を仕上げてから行う。日本版のPMTiles/CloudFront配信は動作確認済みで、この配信方式を再利用する。

## 世界対応に必要な実装

1. **取得と区画管理**: JP限定と日本用の座標ガードを世界用へ置き換える。snapshot・カテゴリ版を固定し、一意ID・件数・座標異常を検査する。国/地域と版のmanifestを用意する。国ごとの件数・登録偏りも記録する。既存トークンの海外・世界版への読取利用も所有者の許可を受けた。
2. **密度の計算**: 日本中心LAEAを世界へそのまま広げない。地域ごとの正積図法や球面上の計算を比較し、同じ件/km²・σの意味を維持する。国境で入力を切らず余白を持たせる。高緯度・日付変更線・重複区画・区画境界の連続性を検査する。Web Mercator表示の緯度上限も説明する。
3. **背景と名称**: 地理院の淡色地図とN02/N03に代わる世界の背景・都市名・行政区域を選び、出典と利用条件を確認する。駅が少ない国でも名前が付く方式、日本語名と現地名の表示、名称の根拠を決める。
4. **配信と画面**: 国/地域ごとのPMTilesとmanifestを登録する。大きな国はさらに分割し、すべての国を同じサイズの単位と仮定しない。現在の全国峰JSON全件読み込みと全国駅datalistを世界全件へ拡大せず、表示範囲に応じた峰の検索/分割・必要分の読み込みへ変更する。表示範囲トップ20の順位と重複除去を維持する。国/地域の選択と全域ボタンを連動させる。

## 方法と記事の仕上げ

局所最大点は既存の暫定仕様で、突出度による独立峰はまだ未実装。独立した山と呼ぶ場合は判定を実装・検証する。平滑化幅としきい値で峰数・順位がどう変わるか記録する。日本の経済センサス比較、登録密度と人出の違い、国ごとの収録偏り、範囲端と海上への平滑化の扱いを記事にまとめる。世界全体の単一順位を実際のにぎわいの国際比較として扱わない。

## 進める順序

- 日本版を保持し、異なる緯度・登録傾向の少数地域で世界用計算・背景・名称を試す。
- 表示範囲で峰を読み込む仕組みと国/地域manifestを固め、同じアップロード処理で配信する。
- 国/地域を順に増やし、計算時間・ファイル量・アクセス時の転送量と費用を測る。
- 方法の検証・出典・記事を仕上げて、最後にGitHub Pagesへ画面を公開する。

### 着手状況（2026-10-06）

`scripts/world-pilots.json`にシンガポール、ロンドン、レイキャビク周辺の試作範囲を定義した。国全体ではない。σ200/400/800m、100m格子を比較し、取得時に最大σの4倍＋550mの余白を加えた。

`scripts/regional_grid.py`は地域中心のLAEAを用い、日付変更線をまたぐ区画の経緯度範囲を2つに分ける。低・中・高緯度の試作3地域で中心・辺・角の1kmの距離と往復変換を検証した。別の投影を持つ地域間の実データの継ぎ目や、日付変更線をまたぐ密度形状、極域の対応は残っている。

`scripts/build_peak_index.py`は峰を二分木で分割し、葉に全件、内部に密度上位100件を保存する。画面内に完全に含まれる区画は要約、画面端に交差する区画は子を検索することで、表示範囲トップ20を保つ。日付変更線をまたぐ画面は呼び出し側で分割が必要。日本の200m・全業種14,912峰から127ファイルの試作索引を作成した。海外試作では画面側への接続・非同期競合処理・通信量の測定を実装・検証した。日本版は従来の峰JSONを読む。

海外3地域のFoursquare取得・計算・配信を完了。publish_data.pyは入力・原本ディレクトリを引数化し、峰索引のサブディレクトリを含む配布検査とアップロードを扱う。日本のv2を保ち、海外はpilots/<region>/2026-09-15-v1/に配置した。

海外の名前参照はOSMの駅名を優先し、駅が遠い場合は都市・地区名を「付近」として補完する処理を実装した。試作3地域の駅・都市名を取得し、地域別密度生成に命名関数を接続。全体の自動テスト24件成功。日本の既定命名は維持。[取得・命名・出典と検証結果](world-names.md)。海外3地域の密度取得と画面切り替え、海外計36条件の配信検証まで行った。[現在の結果と次の段階](world-pilots.md)。
